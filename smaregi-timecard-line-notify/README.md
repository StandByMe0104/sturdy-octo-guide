# スマレジ出退勤 LINE通知

スマレジ・タイムカードの勤怠実績を5分間隔で読み取り、出勤・退勤を管理者のLINEへ通知する
Google Apps Script プロジェクトです。

- 本番のGASプロジェクト: Googleドライブ「スマレジ出退勤ライン通知」
- LINE公式アカウント: StandByMe_AgentBot
- 認証情報（LINEトークン・スマレジの契約ID等）はコードに含めず、
  GASの「プロジェクトの設定」→「スクリプト プロパティ」に入力します。

## 構成

| パス | 内容 |
| --- | --- |
| `src/コード.js` | GASプロジェクト本体 |
| `src/appsscript.json` | GASのマニフェスト |
| `test/harness.js` | GASサービスを模擬してNodeで挙動を確認する簡易ハーネス |

## 修正した不具合: 出勤が二重に通知される

### 症状

同じスタッフの【出勤】が、退勤を挟まずに2回届く。2通目の方が時刻が古い。

```
【出勤】山田太郎 9/21 12:47:05 LIG高田馬場店   ← 12:50に着信
【出勤】山田太郎 9/21 12:41:00 LIG高田馬場店   ← 12:55に着信
```

### 原因

通知済みかどうかを判定する識別子に、打刻時刻そのものが含まれていました。

```js
const key = SMN.donePrefix + digest_([c.contract, r.staffId, r.storeId, pair[0], at].join('|'));
```

この識別子は「この人がこの瞬間に打刻した」という意味になるため、スマレジ側で打刻修正を行って
`attendanceAt` が 12:47:05 から 12:41:00 に変わると、同じ勤怠実績であっても別の識別子になります。
結果、次回のポーリングで未通知の新しい打刻とみなされ、2通目の【出勤】が送信されていました。
1通目を取り消す仕組みもないため、退勤を挟まない出勤が2件並ぶ状態になります。

### 対処

識別子から打刻時刻を外し、勤怠実績そのものを指す組み合わせに変更しました。

```js
const key = SMN.donePrefix + digest_(
  [SMN.keyVersion, c.contract, r.staffId, r.storeId, String(r.shiftDate), ordinal, pair[0]].join('|'));
```

`ordinal` は、同一スタッフ・同一店舗・同一勤務日の勤怠実績を出勤時刻順に並べた通し番号です。
中抜けなどで1日に複数の勤務がある場合も、それぞれ別の打刻として通知されます。

あわせて、通知済み記録の値を `通知した時刻|打刻の時刻` の形式に変更しました。
打刻時刻を保持することで、通知後に打刻が修正されたことを検出できます。
修正を検出した場合は【出勤】を再送せず、修正として1回だけ通知します。

```
【出勤修正】山田太郎
9/21 12:47:05 → 9/21 12:41:00
LIG高田馬場店
```

### 識別方式の移行について

識別子の形式が変わるため、旧方式で記録した通知済みの印は新方式では一致しません。
そのままでは直近の打刻がすべて新規として再通知されてしまうので、
`SMN_KEY_VERSION` を導入し、更新後の最初の1回だけ既存の打刻を
通知済みとして登録してから通常運転に入ります（`seedKnownEvents_`）。

この1回の実行中に発生した打刻は通知されません。
影響を避けたい場合は、打刻の少ない時間帯に反映してください。

## 反映手順

1. GASエディタで対象プロジェクトを開く
2. `src/コード.js` の内容を「コード.gs」に貼り付けて保存
3. `showStatus` を実行し、「打刻の識別方式」が `更新前` と表示されることを確認
4. 次回のトリガー実行（最大5分）を待つ。実行ログに
   「打刻の識別方式を更新しました。既存の打刻は通知済みとして登録しています。」が出れば移行完了
5. 再度 `showStatus` を実行し、「打刻の識別方式: v2」になっていることを確認

スクリプト プロパティの変更は不要です。`stopNotifications` / `startNotifications` も不要です。

## 動作確認

```bash
node test/harness.js src/コード.js           # 識別方式の移行を含む初回
SEED_V2=1 node test/harness.js src/コード.js  # 移行済みの定常状態
```

移行済みの状態で、打刻修正シナリオが以下になることを確認しています。

| 回 | 状況 | 通知 |
| --- | --- | --- |
| 1 | 出勤 12:47:05 | 【出勤】12:47:05 |
| 2 | 12:41:00 へ打刻修正 | 【出勤修正】12:47:05 → 12:41:00 |
| 3 | 変化なし | なし |
| 4 | 退勤 12:55:00 | 【退勤】12:55:00 |
